🎨 どうぶつお絵かきで学ぶ Git と GitHubクマさんの絵に、あなたが好きな動物を描き足そう ― フォークからマージまでの体験

☁️ GitHub（インターネットの上）
💻 あなたのパソコン

📖 ことばずかん

📚リポジトリ

作品をしまっておく保管庫。今の絵だけでなく、これまでのセーブの記録（歴史）も全部入っている。

git init
💾コミット

ゲームのセーブポイント。「いつ・だれが・なにを変えたか」をメッセージつきで記録する。いつでもその時点の絵にもどれる。

git add ファイル git commit -m "メッセージ"
🌿ブランチ

ためし描き用の別ページ。本番の絵（main）をよごさずに、安心して描いたり試したりできる。

git switch -c ブランチ名
🍴フォーク

他の人のリポジトリを丸ごとコピーして、自分のGitHubに置くこと。自分のコピーなので自由に変えられる。

GitHubの Fork ボタン
⬇️クローン

GitHubにあるリポジトリを、自分のパソコンにコピーしてくること。

git clone URL
⬆️プッシュ

パソコンでしたコミットを、GitHubへ送ること。送るまではパソコンの中だけの変更。

git push origin ブランチ名
📨プルリクエスト（PR）

「わたしの変更を、あなたの作品に取りこんでくれませんか？」というお願い。話し合いもここでする。

GitHubの Pull request ボタン
🔍レビュー

変更をチェックしてコメントすること。直して同じブランチにプッシュすると、PRの中身も自動で新しくなる。

🔀マージ

ブランチの変更を合体させて、本番に取りこむこと。

GitHubの Merge ボタン
⚡コンフリクト

同じ場所を、別々の人がちがうように変えて「ぶつかる」こと。どちらにするかは人間が決める。

🔄同期・プル

本家やGitHubの新しい変化を、自分のフォークやパソコンに持ってくること。フォークは自動では新しくならない。

Sync fork git pull
先生向けメモ（本物のGitとの対応と、省略していること）
  • 12×12マスの絵1枚を、リポジトリ内のファイル1つ（oekaki.png）に見立てています。1マスの変更がテキストファイルの1行の変更に相当します。
  • git add（ステージング）とgit commitは1つのボタンにまとめています。左下の「本物のコマンド」には両方を表示しています。
  • 本家をupstream、自分のフォークをoriginとして扱っています。リモートの登録手順は省略しています。
  • 途中で第三者（ペンギン）のPRが本家にマージされ、本家が先に進む状況を作っています。同じマスを双方が変えた場合だけコンフリクトになります（マス単位の3-wayマージ）。
  • マージはマージコミット方式です。フォークの更新はGitHubの「Sync fork」、手元の更新はgit pullで表現しています。
  • データはこのページの中だけで動き、どこにも送信されません。リロードや「さいしょから」で初期状態に戻ります。
